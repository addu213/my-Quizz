QuizMaster

A serverless, real-time, gamified trivia platform for 190 simultaneous players — built on Ably Realtime, distributed as two self-contained HTML files with zero backend hosting.

Ably Realtime Vanilla ES6 Tailwind · QR · Camera

Stack: HTML5 · CSS3 (Tailwind CDN) · Vanilla JS (ES6 Modules) · Ably Realtime Broadcast + Presence · html5-qrcode · qrcode.js

Capacity: Up to 190 students + 1 host on the Ably free tier (200 concurrent connections).

Architecture: Host browser is the sole authority for timing, scoring, and state. Students are thin clients.

Auth: Ably API key embedded in client (see security note in Section 5).

Files in this build: board.html · player.html

1. Executive Summary

QuizMaster is a classroom trivia platform where a teacher runs a board console and students join from their phones by scanning a QR code. Everything is client-side: there is no server to host, no database, and no monthly recurring hosting cost beyond the Ably realtime layer. The teacher's browser owns the authoritative clock and the score ledger; student devices only react to broadcast messages and send signed submissions.

2. Feature Matrix

2.1 Teacher Board Console (board.html)

  • Lobby: Auto-generates a room ID, a join URL, and a QR code. Tracks live presence up to 190 players.
  • Deck editor: Up to 100 questions, each with text, 4 choices (A–D), correct answer, duration, base marks, and penalty.
  • Time-decay scoring: Full marks inside 10 seconds; linear decay to a max 50% penalty at the buzzer.
  • Negative marking: Wrong answers deduct the configured penalty from the score.
  • Live telemetry: Submissions list, leaderboard (top 10), per-player infraction counter.

2.2 Student Mobile Gamepad (player.html)

  • Camera join: In-browser QR scanner (html5-qrcode) — no typing, no app install.
  • Avatar picker: 100 inline Unicode glyphs — zero external assets, zero load lag.
  • State machine: Lobby → Gamepad (large A/B/C/D buttons) → Freeze (locked post-submit or on infraction).

3. Architecture & Data Flow

The system is an asymmetric publisher–subscriber model. The host browser is the single source of truth.

3.1 Presence as the player registry

Ably's presence.enter() is the source of truth for who is in the room. The host subscribes to presence events and re-pulls the full member list on every change, which keeps the roster correct even through mobile reconnects and multi-tab sessions. This removes an entire class of race conditions that a manual join/leave Map would introduce.

6. Security & Anti-Cheat Controls

API key exposure. The Ably key is embedded in client-side JavaScript. Anyone with DevTools can read it. For classroom use this is acceptable; for public deployment rotate the key after each event or move to Ably's TokenRequest flow (Section 7).

6.1 Tab visibility detection

document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden' && gameActive) {
    channel.publish('cheat_flag', { clientId: ably.connection.id, timestamp: Date.now() });
    showLockoutScreen();
  }
});

The host receives cheat_flag, calls logInfraction(), and applies a −50 penalty.

6.2 Host-enforced clock syncing

// Host publishes the authoritative start time
channel.publish('question_start', { ..., startAt: Date.now() });

// Host ignores any submission that arrives after duration
const elapsed = (Date.now() - this.questionStartAt) / 1000;
if (elapsed > q.duration + 0.5) return;

6.3 Atomic input locking

function submitAnswer(choice) {
  if (locked) return;
  locked = true;
  document.querySelectorAll('.option-btn').forEach(b => b.disabled = true);
  channel.publish('answer_submitted', { clientId, submittedChoice: choice, timeElapsed });
}
Limitation: atomic locking is client-side only. A student with DevTools can re-enable buttons. This is a classroom deterrent, not a hard boundary. For high-stakes exams, use a server-authoritative model.

7. Deployment & Run Guide

7.1 Local test

  1. Save the two code blocks as board.html and player.html in the same folder.
  2. Serve the folder over HTTP (camera APIs require HTTPS or localhost): 
    python3 -m http.server 8000
  3. Open http://localhost:8000/board.html on your laptop. A QR appears.
  4. Open http://localhost:8000/player.html on your phone (or a second tab) — scan or type the room ID.

7.2 Production (free hosting)

  • Netlify Drop — drag the folder at app.netlify.com/drop. You get an HTTPS URL. Camera + QR work immediately.
  • GitHub Pages — push to a repo, enable Pages. HTTPS is automatic.
  • Cloudflare Pages — same, and free SSL.

7.4 Rotating the Ably key (recommended after every event)

  1. Ably Dashboard → your app → API Keys → Revoke & create new.
  2. Replace the ABLY_KEY string in both HTML files.
  3. Redeploy.

7.5 Token-based auth (production hardening)

To avoid shipping the key to clients, issue short-lived tokens from a serverless function (Netlify / Cloudflare / Vercel). The client calls your function, receives a TokenRequest, and passes it to new Ably.Realtime({ authUrl: '/api/ably-token' }) instead of key. Ably's docs call this the "Token Request" flow.

9. Scoring Formula

function calculateScore(baseMarks, timeElapsed, duration) {
  const FULL_GRACE = 10;                     // full marks inside 10s
  if (timeElapsed <= FULL_GRACE) return baseMarks;
  const decayWindow = Math.max(1, duration - FULL_GRACE);
  const ratio = Math.min(0.5, ((timeElapsed - FULL_GRACE) / decayWindow) * 0.5);
  return Math.round(baseMarks * (1 - ratio)); // floor = 50% of base
}
